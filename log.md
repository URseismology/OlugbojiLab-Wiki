## 2. Data Architecture

### Data Patterns
The data architecture is designed to ensure efficient and reliable data management. The system follows a three-tiered approach:

1. **Data Access Layer (DAL)**:
   - **Database Interactions**: The DAL handles all interactions with the database, including fetching and storing data.
   - **Models**: Defines the structure of the data entities used in the system.

2. **Business Logic Layer (BLL)**:
   - **Rules Implementation**: Implements business rules and processes that define how data should be transformed and enriched.
   - **Processes**: Contains the logic for performing specific tasks on the data, such as validation, aggregation, and filtering.

3. **Service Layer (SL)**:
   - **API Endpoints**: Provides external access to the system's functionalities through well-defined APIs.
   - **Services**: Manages the orchestration of services and ensures that they are available and responsive.

### Data Flow
- **Data Retrieval**: The Service Layer receives requests from external systems or other subsystems.
- **Processing**: The request is passed to the Business Logic Layer, where it is processed according to predefined rules.
- **Storage**: The transformed data is then stored in the database via the Data Access Layer.
- **Response**: The Service Layer returns a response to the requesting system.
