# Dr O Jupyter Labs: Operational Guide

This document is the operational manual for the centralized student lab environments. It provides instructions for Students, Teaching Assistants (TAs), System Administrators, and AI Agents on how to use, manage, and deploy resources on the JupyterHub system.

## 1. Student Access & The Lab Environment

Instead of installing local Python and managing dependencies, students are provided with a powerful, pre-configured cloud workspace.

*   **Accessing the Hub:** Navigate to `https://urseismogate.earth.rochester.edu/lab/`.
*   **Authentication:** The system uses `NativeAuthenticator`. Students can click "Sign Up" to create an account, which the Administrator will subsequently authorize.
*   **The Workspace:** Once logged in, students can select their profile from a dropdown menu. The system will then dynamically spawn an isolated Docker container (`urseismo/student-lab` or `urseismo/student-lab-gpu`) onto the Swarm network.
*   **Data Persistence:** The student's environment is directly mapped to a private directory on the 160TB Synology NAS. Even if the Docker container is deleted or updated, their code and data are safely preserved on the NAS at `/mnt/production_uploads/class_work/{username}`.

## 2. Pushing Assignments & Data to Students

To manage the logistics of distributing labs and datasets to an entire class simultaneously, we have automated the process with a deployment script.

*   **The Staging Area:** Teachers and TAs place the assignment files (notebooks, datasets) into the staging directory on the NAS:
    *   `/mnt/production_uploads/pushlabs/`
    *   *(Note: Anything placed here will be sent to all students. Do not upload answer keys!)*
*   **The Deployment Script:** Run the deployment script on the `terra4-classnode` server:
    *   `~/jupyterhub_server/push_lab.sh`
*   **How it Works:** The script iterates through every student directory, securely copies the assignment files, and automatically assigns the correct permissions (`chown 1000:100`) so students have immediate read/write access. This allows agents and TAs to instantly distribute code without manual transfers.

## 3. Socratic AI & GPU Access

To assist students with complex coding challenges, the lab features an integrated, strictly-guided AI assistant backed by raw GPU computing power.

### The Socratic Coding Assistant
*   **The Interface:** The student Docker image comes pre-installed with the `jupyter-ai` extension. Students can open the chat panel directly inside their Jupyter notebook.
*   **The Routing:** The environment is pre-configured with `OLLAMA_HOST=http://128.151.53.156:11434`. When a student asks a question, the request is tunneled out of their container and securely sent to the `terravibranium-gpu` inference node.
*   **The Rules:** The backend runs a customized `coding-assistant` model. This model is bound by a strict system prompt preventing it from generating direct code solutions. Instead, it acts as a digital TA, asking leading questions and offering pseudo-code hints to guide the student's learning process.

### Full PyTorch GPU Access (For Advanced Students)
While standard workloads run on the CPU `terra4-classnode`, advanced projects requiring heavy PyTorch training can leverage dedicated hardware.
*   **The Dedicated Node:** `terravibranium-gpu` is sized specifically for interactive student coding, deep learning, and small debug sessions.
*   **Deployment Architecture:** Using Docker Swarm and `wrapspawner.ProfilesSpawner`, users simply select the "PyTorch GPU Lab" from the JupyterHub dropdown menu. The system automatically places the container on `terravibranium-gpu` using the `gpu=true` node label constraint, and natively mounts the NVIDIA GPU into the container via the `nvidia` container runtime.

## 4. Teaching Assistant (TA) Socratic AI Reporting

Because all Jupyter AI chat histories are permanently mounted to the NAS, TAs can easily generate analytics on how students are interacting with the coding assistant. 

TAs can run the `ta_reporting_script.py` script directly on `terra4-classnode` or `terravibranium-gpu` to extract the number of interactions, messages sent, and estimated lines of code generated by the AI for each student.
