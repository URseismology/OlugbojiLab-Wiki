# Literature Parsing Architecture

To manage and analyze the lab's massive PDF library without losing structural fidelity of older scanned documents, we developed a local Deep-Learning OCR pipeline on the `inferencelocal` GPU node.

## 1. The Architecture

The entire pipeline is codified in `AIBot_PaperCrafter.py`. It runs iteratively to safely ingest and analyze PDFs directly from the Synology NAS. 

### Secure Ingestion & Deduplication
The pipeline securely mounts `repovibranium` via SFTP to search for new `.pdf` files in the `Paperpile` and `All Papers` directories. Before processing, it generates a SHA-256 hash of the remote file path and checks the local SQLite Database. If the paper has already been processed, it is instantly skipped, allowing the daemon to run continuously and recover from crashes seamlessly.

### Deep-Learning OCR (`marker-pdf`)
Instead of standard text parsers (like PyMuPDF) which completely fail on historical scanned documents (e.g., Gabor 1946), the pipeline utilizes `marker-pdf` v0.3.10. This runs native PyTorch models directly on the RTX 3090 GPUs to visually parse and transcribe scanned images into perfect Markdown format.

### Metadata Enrichment & API Lookup
The raw Markdown is scanned using regex to extract a clean DOI (e.g., `10.1073/pnas.2013806117`). If a DOI exists, the pipeline queries the `OpenAlex API` to retrieve clean, standardized metadata. If a DOI is missing (e.g., historical papers), the pipeline automatically extracts the paper's title from the Paperpile filename and searches the OpenAlex API using a title-fallback query. 
This process captures:
* **Title**
* **Authors**
* **Journal Name**
* **Publication Year**
* **Citation Count (OpenAlex)**

*(Note: The database also explicitly provisions a `semantic_scholar_citations` column for future backfilling via the Semantic Scholar API.)*

### AI Synthesis (`Qwen2.5-72B`)
To maximize analytical fidelity, the pipeline dynamically attempts to feed the **entire** OCR-extracted Markdown file (often 200,000+ characters) to `Qwen2.5-72B` running on local Ollama. If the file exceeds the model's physical context window (triggering an HTTP 400 rejection), the script recursively truncates the text in half and retries until it fits. The API-extracted metadata (Title, Authors, Citations) is injected directly into the LLM prompt block, forcing the AI to synthesize a strict 3-sentence summary covering the paper's core hypothesis, methodology, and conclusion while being aware of the paper's real-world influence.

## 2. Output & Artifact Generation

The pipeline generates three critical outputs for human consumption and downstream AI Agents:

1. **Master SQLite Database:** The metadata and AI summaries are centralized into a SQLite `.db`. This database enforces structured schemas and heavily indexes `cited_by_count` and `publication_year`, enabling lightning-fast, Web-of-Science style literature surveys (e.g. instantly querying the top 10 most influential papers of a specific decade).
2. **JSONL Output and Deep-Dive Cross-Referencing:** Standalone `.jsonl` files are created per paper, and appended to a `Master_PaperCrafter_Index.jsonl`. Crucially, these dictionaries contain a `full_text_local_path` key. This allows Cloud AI Agents to instantly scan the lightweight JSONL for relevant papers, and follow the absolute file path directly to the massive raw OCR text for deep-dive RAG analysis.
3. **Raw Markdown Extraction:** The massive full-text markdown output generated by the deep-learning OCR is preserved untouched in the `full_texts/` directory.
